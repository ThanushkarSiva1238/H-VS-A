# Human vs AI — Guess the Translation?

An interactive dark-fantasy dungeon RPG built for a live academic presentation.
Players choose Monolingual or Bilingual mode, enter a mystery dungeon, and try
to spot which of two translations was generated by AI. No build step, no
backend — pure HTML/CSS/JS, ready for GitHub Pages.

## Files

```
index.html    Main app: lobby → gates → reveal → challenge → result →
              explanation → process → QR screen
result.html   Mobile-friendly page the QR code opens (full result sheet
              + PDF download)
style.css     Dark-fantasy RPG design system (all screens)
data.js       All challenge content (4 dungeons × mono/bilingual ×
              English/Tamil) — edit this to swap in real content
shared.js     Highlight-tooltip parsing, result encode/decode, PDF builder
script.js     Game logic for index.html
.nojekyll     Tells GitHub Pages to serve files as-is
```

### A note on the PDF and Tamil text

The downloaded PDF is generated by rendering the result sheet as normal
HTML off-screen, then photographing that layout into the PDF page
(`html2canvas` + `jsPDF`) rather than asking a PDF library to draw the
text itself. This matters for Tamil: PDF text-drawing libraries place
glyphs one Unicode codepoint at a time with no script shaping, and Tamil
needs certain vowel signs to be visually reordered around the consonant
they follow — so drawing it directly comes out jumbled no matter which
Tamil font is embedded. Letting the browser lay the text out (the same
engine that already renders Tamil correctly on screen) and rasterizing
that avoids the problem entirely, for Tamil or any other script.

Content is fully separated from UI (`data.js`), so replacing the placeholder
paragraphs later means editing that one file only — nothing else needs to
change.

## How the result sheet works (no backend needed)

When a player finishes a challenge, their result (dungeon, mode, answer,
correct answer, timestamp) is compressed into a short code and embedded as a
`?d=...` query parameter on a link to `result.html`. The QR code just points
to that URL. Scanning it opens `result.html` on the player's phone, which
decodes the parameter and re-renders the full result sheet — including a
**Download Result as PDF** button — using the same `data.js` content, so
nothing needs to be stored on a server.

## Run it locally

Any static file server works, e.g.:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

(Opening `index.html` directly via `file://` also works, but a local server
avoids any browser quirks with query-string links to `result.html`.)

## Deploy to GitHub Pages

1. Create a new repository on GitHub (e.g. `human-vs-ai`).
2. Upload all the files in this folder to the repository root (keep the
   flat structure — don't nest them in a subfolder), **or** from your
   terminal:
   ```bash
   cd human-vs-ai
   git init
   git add .
   git commit -m "Human vs AI — Guess the Translation?"
   git branch -M main
   git remote add origin https://github.com/<your-username>/<repo-name>.git
   git push -u origin main
   ```
3. In the repository, go to **Settings → Pages**.
4. Under **Build and deployment**, set **Source** to `Deploy from a branch`,
   branch `main`, folder `/ (root)`, then **Save**.
5. GitHub will publish the site at:
   `https://<your-username>.github.io/<repo-name>/`
6. Open that URL on the presentation screen. QR codes generated during the
   game will automatically point to the correct published URL — no code
   changes needed after deploying.

## Presentation notes

- Built for 16:9 desktop/projector screens, responsive down to mobile.
- All animation is CSS-only or lightweight DOM injection — no heavy canvas
  work — so it stays smooth during a live demo.
- The two external libraries (`qrcode-generator` for the QR code,
  `jsPDF` + `html2canvas` for the PDF export) are loaded from
  `cdn.jsdelivr.net` in `index.html`/`result.html`; an internet
  connection is required for QR code generation and PDF export.
- To swap the placeholder Academic/Technical/Legal/Literature content for
  real material, edit the `DUNGEONS` object in `data.js`. Use
  `[[phrase||tooltip text]]` inside any `explanationMono`/`explanationBi`
  string to add a new interactive highlight.
